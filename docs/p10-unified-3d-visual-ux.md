# P10 통합 3D 시각 UX — 라벨·강조·상태 색 공통화

워셔액 전용 3D 이름표(`capLabel`)를 모든 모델링 부품이 쓰는 PartLabel 시스템으로 바꾸고, 선택 강조·점검 결과 색·선택 가능 힌트를 서로 다른 역할로 분리했다. 목록의 기본 테두리는 중립색으로 통일했다. 결과는 [증거 인덱스](evidence/p10-unified/README.md)에 있다. **데스크톱 Chrome 측정이며 AVD, Android WebView, 실제 손가락 터치, 스마트폰은 `NOT_RUN`이다.**

이전 PR에서 해결된 부분은 다시 구현하지 않았다. 부품 레지스트리(PR #96), 카메라 프레이밍·차체 통과 방지·상세/결과/이력 시점(PR #98), 워셔액 안내 문구(PR #97)는 그대로 쓴다.

## PartLabel (`tools/three-poc/part-labels.mjs`)

Three.js와 DOM에 의존하지 않는 순수 모듈이다. 페이지(`inspect.js`)는 투영 좌표, 가림 여부, 요소 크기, 패널 위치만 넘긴다.

| 규칙 | 내용 |
|---|---|
| 이름·ID | `inspection-parts.mjs`의 `partLabel`만 쓴다. 영역 이름은 `inspection-flow.mjs`의 `INSPECTION_AREAS`다. |
| 대상 | `geometrySource`가 `NONE`이 아닌 18개 부품. 저전도 냉각수(`NONE`)는 라벨·대체 위치·가짜 메시 없이 목록에서만 연다. |
| 화면별 노출 | 보닛 목록·미리보기: 보닛 5개 부품. 타이어: 4개. 충전구 2개, 와이퍼 2개, 전조등 4개는 각 영역 미리보기에서. EV 배터리·결과 화면: 선택한 부품 하나. 개요·전체 요약: 영역 이름 5개(보닛, 타이어, EV 충전구, 전면 와이퍼, 전조등). 한 화면 최대 6개. |
| 이벤트 | 라벨은 그 화면에서 같은 부품 메시를 눌렀을 때와 같은 흐름 이벤트를 보낸다(`SELECT_COMPONENT`, `SELECT_TIRE`, `SELECT_CHARGE_PART`, `SELECT_VISIBILITY_PART`, `SELECT_AREA`). 선택된 라벨은 아무것도 보내지 않는다. |
| QR·모바일 진행 중 | 수신 단계가 `AUTH_WAITING`, `CREATING`, `QR_READY`, `CONNECTED`, `RESULT_RECEIVED`이면 선택 부품 라벨만 남고 이벤트를 보내지 않는다. 워셔액 QR 화면(`MOBILE_HANDOFF_READY`)도 같다. 잘못된 터치로 QR 단계를 떠나는 경로를 새로 만들지 않는다. |
| 결과 표시 | 라벨에 결과 기호(○ ! ? −)를 표시하고 선택 라벨에는 상태 이름까지 쓴다. 보조기술 이름은 "부품, 상태"다. 색만으로 상태를 전하지 않는다. |

### 배치와 숨김

`layoutLabels`가 우선순위(선택 부품 먼저) 순서로 배치한다. 숨길 때는 이유를 남긴다.

| 이유 | 조건 |
|---|---|
| `BEHIND` | 기준점이 카메라 뒤 |
| `OFFSCREEN` | 기준점이 화면 밖 (가장자리 8px 포함) |
| `COVERED` | 기준점이 패널, 상단 바, Android 확대 버튼, 개발 패널 위 |
| `OCCLUDED` | 다른 메시가 부품을 가림. **선택한 부품은 숨기지 않고 점선 테두리와 "가려짐"으로 표시**해 위치를 알린다. |
| `NO_SPACE` | 화면, 패널, 다른 라벨, 다른 라벨의 기준점과 겹치지 않는 자리가 없음 |
| `LIMIT` | 한 화면 최대 개수 초과 |

후보 위치는 부품 화면 상자의 위·아래·오른쪽·왼쪽을 먼저 쓰고, 그다음 기준점 옆이다. 라벨이 자기 부품을 덮지 않게 하기 위해서다. 라벨 버튼은 최소 44×44px이다.

### 가림 판정

부품마다 경계 상자 중심과 정점 표본(최대 14개)을 만들고, 카메라에서 각 점으로 광선을 쏴 처음 맞는 메시가 그 부품이면 그 지점을 기준점으로 쓴다. 모든 표본이 다른 메시에 먼저 맞으면 가려진 것으로 본다. 투명 렌즈(`Lens_Smoked`)와 보이지 않는 메시는 기존 `nearestInspectionHit` 규칙대로 건너뛴다. 카메라·보닛·화면 크기가 바뀔 때 최대 150ms마다, 화면 전환 직후에는 즉시 다시 판정한다. **표본 점 판정이므로 부품의 모든 점이 보이는지 증명하지 않는다.**

## 터치 보정

`pointerup`의 `pointerType`으로 입력을 구분한다. **마우스와 펜은 정확한 위치만** 판정하고, 보정은 **손가락(`touch`)에만** 쓴다. hover도 정확한 위치다. 판정 규칙은 `part-labels.mjs`의 `chooseTouch`이며 CI에서 검사한다.

1. 정확한 위치에 선택 가능한 대상이 있으면 그것을 고른다. 보정은 이를 덮어쓰지 않는다.
2. 정확한 위치가 비어 있으면 반경 16px 안의 링(약 5px, 11px, 16px)을 실제 광선으로 판정한다.
3. 반경 안에 선택 가능한 대상이 **하나뿐인 특정 부품**일 때만 고른다(`SLOP`).
4. 반경 안에 대상이 둘 이상이면(다른 부품이든 보닛 같은 영역 전체든) 의도가 불명확하므로 아무것도 고르지 않는다(`AMBIGUOUS`). 그 부품은 3D 라벨이나 목록으로 고른다.
5. 영역 전체 대상(개요의 보닛, 부품 지정 없는 `SELECT_AREA`)은 보정으로 닿지 않는다(`AREA_ONLY`). 보닛은 정확히 눌러야 열린다.

**PR #117 리뷰 수정.** 첫 구현은 반경 안에서 처음 맞는 대상을 골랐다. 그래서 전조등 표식을 노린 탭이 보닛을 열었고(기준선 4건), 420×860에서는 옆 타이어나 옆 전조등을 고르기도 했다. 마우스 클릭에도 보정이 적용됐다(1024×600 왼쪽 와이퍼 1건). 지금 규칙에서는 이런 경우를 고르지 않는다. 라벨 버튼은 별도의 44px 대상이다.

## 강조 역할

| 역할 | 표현 | 적용 |
|---|---|---|
| 결과 | 재질 기본 색을 상태 색으로 바꾼다. `NOT_INSPECTED`는 **모든 부품에서** 원래 재질을 유지한다(타이어 예외 제거). | 기존 계약 4개 상태 색(`inspection-state-map.mjs`) 그대로 |
| 선택 | 청록 발광 + 청록 외곽선. 발광 세기를 재질 밝기로 보정해 어두운 재질은 더, 밝은 재질은 덜 받는다. 결과 색이 있으면 발광이 결과 색 휘도의 50%를 넘지 않는다. | 선택 부품만. 타이어는 고무와 휠(터치 대상 전체) |
| 힌트 | 중립 회백색(`#d9e2ec`) 약한 발광. 동작 줄이기 설정이면 맥동하지 않는다. | 개요·전체 요약(보닛·타이어·와이퍼·전조등·충전구), 보닛 목록, 타이어 목록 |

청록은 선택에만 쓴다. 개요의 보닛 맥동과 보닛 외곽선도 중립 힌트 색으로 바꿨다. 결과 색은 타이어 고무에만 칠하는 기존 계약을 유지한다.

## 목록

모든 행의 기본 테두리는 중립색(`--line`)이다. `available`/`preview`의 청록·갈색 테두리와 경고색 태그를 없앴고, 태그 문구(`점검 가능`, `형상 보기`)는 그대로다. 실제로 선택된 행(`aria-pressed="true"`)만 청록 테두리와 왼쪽 막대를 쓴다. 결과 배지는 기존대로 기호와 문구를 함께 쓴다.

## 바꾸지 않은 것

Pleos SDK 데이터 계약, Android Native QR·인증·수신, 모바일 Vision·Roboflow·GPT, Render·Supabase·DB, 결과 원본·상태 스키마·이력, 전체 요약 정보 구조와 내비게이션(PR #2 범위), 카메라 프레이밍과 경로(PR #98), 흐름 상태 전이.

## 남은 위험과 미검증

- **P1-13 OPEN.** 개요에서 전조등 표식은 하우징에 가리고 충전구는 반대쪽이라 손가락 대상이 없다. 영역 미리보기에는 부품별 44px 라벨이 있다.
- 터치 보정은 반경 안에 대상이 하나뿐일 때만 동작한다. 전조등 표식 주변은 거의 항상 보닛이 함께 있어 보정이 동작하지 않는다(의도한 보수적 동작, P1-13 OPEN의 원인 중 하나).
- 좁은 화면(1024×600, 420×860)의 보닛 목록에서 퓨즈박스 라벨은 자리가 없어 숨는다(목록 접근 가능).
- 선택 휘도 편차 0.222는 기준 0.25에 가깝다. 조명·시점이 바뀌면 달라질 수 있다.
- 어두운 재질(타이어 고무·휠, 배터리 케이스)은 선택 발광이 최대 1.0이라 청록이 강하게 보인다.
- 가림은 표본 점 판정이며, 회전 검사는 네 자세 표본이다. 모든 각도의 증명이 아니다.
- AVD, Android WebView, 실제 손가락, 스마트폰, 실차는 **NOT_RUN**이다. 모바일 결과는 스크립트 어댑터로만 넣었다.
