# P12-F 보닛 부품 실제 AI 탐지 통합

P12-E의 흐름을 실제 Roboflow 호스팅 모델 `engine-bay-parts/1`과 연결하고, 6개 부품을 실제 호출로 평가했다. **실제 추론은 로컬 실험 진입점에서만 켜진다. 운영 플래그는 꺼져 있다.** 실행 근거는 [증거 인덱스](evidence/p12-f/README.md)에 있다.

## 판정

**연결은 동작한다. 성능은 후보 표시 실험 수준이고 제품으로 켤 수준이 아니다.** 어느 부품도 `VERIFIED`가 아니다.

| 부품 | 모델 클래스 | 상태 | 사진 / 양성 | TP / FP / FN | Precision (95%) | Recall (95%) |
|---|---|---|---|---|---|---|
| 워셔액 주입구 | `Windshield Wiper Fluid` | `EXPERIMENTAL` | 16 / 14 | 6 / 0 / 8 | 1.00 (0.61~1.00) | 0.43 (0.21~0.67) |
| 냉각수 리저버 | `Engine Coolant Reservoir` | `EXPERIMENTAL` | 15 / 13 | 4 / 2 / 9 | 0.67 (0.30~0.90) | 0.31 (0.13~0.58) |
| 브레이크액 리저버 | `Brake Fluid` | `EXPERIMENTAL` | 18 / 17 | 7 / 1 / 10 | 0.88 (0.53~0.98) | 0.41 (0.22~0.64) |
| 모터룸 퓨즈박스 | `Fuse Box` | `EXPERIMENTAL`, 표본 부족 | 5 / 3 | 1 / 0 / 2 | 1.00 (0.21~1.00) | 0.33 (0.06~0.79) |
| 12V 보조 배터리 | 없음 (`Battery`는 측정만) | `UNSUPPORTED` | 17 / 14 | 6 / 0 / 8 | 1.00 (0.61~1.00) | 0.43 (0.21~0.67) |
| 저전도 냉각수 리저버 | 없음 | `UNSUPPORTED` | 라벨 없음 | 평가 불가 | | |

신뢰도 0.4(서비스 기준), IoU 0.5, `EXPLORATORY_EVALUATION` 예비 수치다. **라벨은 단일 자동 작업자(Claude)가 붙였고 사람이 검수하지 않았다.** 정답 라벨이 있는 사진만 셌다. 판단하지 못한 부품은 `unknown`으로 두고 해당 사진의 집계에서 뺐다.

상태 분포 4 `EXPERIMENTAL` / 2 `UNSUPPORTED`는 P12-E와 같다. `Battery` 행은 지원 판단을 위한 측정이며 화면에 노출되지 않는다.

## 평가 방법

- **사진 26장.** P12-C의 Commons 12장(저장된 응답 재사용, 호출 0회)과 새 Commons 14장(실제 호출 14회). 전동화 차량 16장, 차종 23종. IONIQ 5 사진은 없다.
- **순서.** 라벨과 채점 규칙을 [`p12-f-bonnet-parts.json`](../tools/vision-poc/dataset/p12-f-bonnet-parts.json)에 넣어 커밋 `2055840`으로 먼저 고정한 뒤 호출했다. 호출 뒤 라벨을 바꾸지 않았다. 다만 P12-C 12장은 응답 수치를 이전 작업에서 본 적이 있어 완전히 독립적이지는 않다.
- **새 라벨의 한계.** 사진 속 형태와 표시로 판단했고 정비 문서로 확인하지 않았다. 차종별 위치를 몰라 애매하면 `unknown`으로 두었다. 그래서 쉬운 사례 쪽으로 치우쳤을 수 있다.
- **두 기준.** IoU 0.5인 엄격 기준과, 상자 중심이 부품 위에 있고 면적이 4배 이하인 위치 기준을 계산했다. 이번 표본에서는 임계값 4개, 부품 5개 모두 두 기준의 결과가 같았다.
- **숫자 클래스.** `"3"`, `"6"`, `"12"`, `"15"` 같은 숫자 클래스가 0.4 이상에서 자주 나온다(각 11, 16, 11, 12회). 뜻이 확인되지 않아 **세지 않았고**, 이 때문에 Recall이 낮게 나왔을 수 있다.

### 임계값별 TP / FP / FN

| 부품 | 0.05 | 0.25 | 0.4 | 0.5 |
|---|---|---|---|---|
| 워셔액 | 8 / 2 / 6 | 8 / 1 / 6 | 6 / 0 / 8 | 5 / 0 / 9 |
| 냉각수 | 7 / 4 / 6 | 5 / 2 / 8 | 4 / 2 / 9 | 3 / 1 / 10 |
| 브레이크액 | 10 / 2 / 7 | 8 / 1 / 9 | 7 / 1 / 10 | 7 / 0 / 10 |
| `Battery` | 8 / 3 / 6 | 8 / 0 / 6 | 6 / 0 / 8 | 6 / 0 / 8 |
| 퓨즈박스 | 1 / 0 / 2 | 1 / 0 / 2 | 1 / 0 / 2 | 1 / 0 / 2 |

임계값은 바꾸지 않았다. 사후에 고른 값은 낙관적이고, 라벨 검수 전에 조정할 근거도 없다.

## 질문별 답

| 질문 | 답 |
|---|---|
| 실제로 탐지되는가 | 절반 이하다. 부품이 있어도 0.4 기준으로 57~69%를 놓쳤다. |
| 캡인가 전체인가 | 부품별로 다르다. 워셔액 상자는 캡 면적의 중앙값 1.63배로 **캡 주변**이다. 냉각수(1.11배), 브레이크액(1.37배)은 라벨 기준 **리저버 전체**에 가깝다. `Battery`는 1.17배로 본체 전체다. |
| 좌표가 맞는가 | 집계에 잡힌 탐지는 맞다. TP 상자의 위치를 겹쳐 그린 이미지로 확인했다. |
| 근접 사진 | 약하다. 브레이크액 근접(`commons-066`)과 퓨즈박스 근접(`new-06`) 모두 해당 클래스가 없었다. |
| 사진을 바꿔도 일관적인가 | 차에 따라 다르다. Chevrolet Bolt 3장은 브레이크액을 3장 모두 찾았고 배터리는 라벨된 2장 모두 찾았다. Nissan Leaf 2장은 0.4 이상 탐지가 `new-00`에 없고 `new-04`에는 라벨된 부품의 탐지가 없다. 같은 Bolt의 퓨즈박스 상자는 1장에만 나왔다. |

### 집계 밖에서 눈으로 본 오탐 (사후 관찰)

라벨이 `unknown`인 사진의 상자는 **표의 FP에 들어가지 않는다.** 그래서 표의 Precision은 실제 사용보다 높을 수 있다. 겹쳐 그린 이미지에서 본 것이며 라벨 검수를 거치지 않았다. 사후 관찰이므로 수치에 더하지 않았다.

| 사진 | 상자 | 관찰 |
|---|---|---|
| `new-08` Mercedes 250S | 워셔액 0.61 | **라디에이터 캡 위.** 명백한 오인 |
| `commons-039` Hyryder | 워셔액 0.59 | 녹색 캡 통 위. 오인으로 보임 |
| `commons-159` C200 | `Battery` 0.58 | 큰 검은 덮개. 판단 불가 |
| `commons-094`, `commons-041`, `commons-036`, `commons-047`, `new-04` | 퓨즈박스 0.45~0.59 | 뚜껑 있는 검은 상자. 진짜인지 판단 불가. `094`에는 2개 |

집계에 들어간 FP: 냉각수 `commons-170`(호스 영역 0.53), `commons-039`(노란 캡 통 0.41), 브레이크액 `commons-024`(바로 옆 부품 0.48).

## 12V 보조 배터리

**`UNSUPPORTED` 유지.** 위험한 혼동의 증거는 없지만 12V라고 확정할 근거도 없다.

- **좋은 신호:** `Battery` 상자가 라벨한 고전압 영역(사진 12장)과 겹친 경우가 0.05 기준까지 0건이다. 고전압 부품이 크게 보이는 Prius v에서도 상자가 없었다.
- **부족한 이유 1:** 그 영역은 인버터와 덮개다. **고전압 배터리 자체가 보이는 사진이 없어** 가장 중요한 혼동을 시험하지 못했다.
- **부족한 이유 2:** 전동화 차량의 Recall이 3/9이다. Leaf 2장, Ora, Dacia, Focus Electric, Hyryder를 0.4 기준에서 놓쳤다.
- **부족한 이유 3:** 클래스의 정의가 공개되어 있지 않다. 학습 데이터 대부분이 내연기관으로 보인다.

**해결 방안:** 전기차 고전압 팩·서비스 커버가 보이는 사진과 12V 사진을 함께 모은 혼동 평가에서 고전압 오탐이 0인 것을 사전 기준으로 확인한다. 통과 전까지 그림 안내만 쓴다.

## 저전도 냉각수 리저버

**`UNSUPPORTED` 유지. 이 모델로는 불가능하다.**

- 대응 클래스가 없다. `Inverter Coolant Reservoir`는 0.25 이상에서 26장 중 1번 나왔다(Corolla Hybrid 0.65, 평가 전에 `ignore`로 둔 통 위). `Secondary Coolant Reservoir`는 0.25 이상에서 0번이다. 학습 라벨도 각 24개, 8개뿐이다. 어느 쪽도 저전도와 같다는 근거가 없어 매핑하지 않았다.
- `Engine Coolant Reservoir`가 전기차의 통에 나온다(Bolt 2개, Leaf 등). 일반 냉각수와 저전도를 구별하지 않으므로 냉각수 후보가 저전도 통일 수 있다. 화면의 주의 문구에 이미 적혀 있다.
- 공개 대안은 찾지 못했다. Roboflow Universe를 검색 엔진으로 찾았을 때 전용 데이터셋이 없었고, Universe 자체는 자동 접근이 막혀 **직접 전수 조사하지 못했다.** 없다는 증명이 아니다.
- 이 사진 세트에는 IONIQ 5 엔진룸이 없어 실물 대조도 못 했다. Commons 검색 결과는 외관 사진뿐이었다.

| 후속 방안 | 내용 | 평가 |
|---|---|---|
| **A. 차종 한정 소량 학습 (권장)** | 소유자 동의를 받은 E-GMP 실물 사진을 사람이 라벨링해 저전도 클래스를 학습. 허용 라이선스 모델 사용 | 권리 문제까지 함께 풀림. 데이터 수집과 별도 승인 필요 |
| B. 통 탐지 + 표기 읽기 | 통을 찾은 뒤 표기·캡 문구를 OCR로 확인 | 표기가 없는 차에는 안 됨. 검증 전 |
| C. 차종 기반 그림 안내 유지 | AI 없이 차종별 SVG로 위치 안내 | 현재 동작. 비용과 위험이 가장 적음 |

연식에 따라 저전도 냉각수를 쓰지 않는다는 비공식 주장도 있어(미검증), A를 고르면 대상 연식부터 설명서로 확인해야 한다.

## 추가 데이터 계획

**사진이 부족하다.** 퓨즈박스는 양성 3장이고, 저전도는 0장이다.

1. **라벨 검수:** 사람이 [`p12-f-bonnet-parts.json`](../tools/vision-poc/dataset/p12-f-bonnet-parts.json)을 검수한다. 가장 싼 다음 단계다.
2. **기준 선정:** 사진을 더 보기 전에 부품별 합격 기준을 정한다. 예: 95% 구간 하한 Precision 0.8, Recall 0.6. 예시일 뿐 합의된 값이 아니다.
3. **IONIQ 5 수집:** 소유자 동의(외부 전송 포함)로 조명·거리·각도를 나눠 찍는다. 12V·저전도·고전압 표시·퓨즈박스를 포함한다.
4. **혼동 세트:** 퓨즈박스와 다른 전장 상자, 브레이크액과 클러치·파워 스티어링 통, 근접 사진, 부품이 없는 음성 사진.
5. **기존 기준:** 정식 평가는 `DATASET_GATE`(차량 30대, 양성 300장 등)를 그대로 쓴다. 이번 사진은 그 기준을 충족하지 않는다.

## 서버 연결

```text
휴대폰 페이지 ── POST /v1/part-detections/:partId (동의, QR 토큰, JPEG) ──> 서버 라우트
                                                                            │ hostedDetectionProvider
                                                                            ▼ measuredProvider + 호출 원장
                                                                     roboflow-client → serverless.roboflow.com
휴대폰 페이지 <── 이 부품 후보 + detection 기록 ── roboflow-adapter → candidatesFor
```

| 변경 | 내용 |
|---|---|
| `tools/vision-poc/scripts/part-detection-local.mjs` | **새 로컬 진입점.** 기존 클라이언트·파서·라우트를 조립 |
| `tools/vision-poc/src/call-ledger.mjs` | 실제 호출 원장. 파일에 누적, 호출 전 차감, 20회 초과 거부 |
| `part-detection-route.mjs` | 응답에 `detection` 추가. 모델이 보고한 크기와 사진의 비율이 다르면 503 |
| `part-detection.mjs`, `part-detection-ui.mjs`, `sync-client.mjs` | `detection`을 후보와 함께 보관. 지원 사유를 실측값으로 갱신 |
| `tools/vision-poc/src/part-evaluation.mjs`, `scripts/part-eval-*.mjs` | 평가와 리포트. 저장된 응답을 재사용 |

바꾸지 않은 것: 클래스 매핑, 임계값 0.4, 모델 ID, UI 흐름과 문구, 호출 제한, QR·세션·WebXR 계약, Supabase 스키마, 환경변수.

오류 처리: 401·402·429·5xx·잘못된 JSON·소켓 오류·시간 초과·원장 소진은 모두 고정된 503 `PART_DETECTION_UNAVAILABLE`이고 화면은 `AI 서비스에 연결하지 못했어요`와 그림 안내를 보여 준다. 상류 메시지는 전달하지 않는다. 신뢰도와 좌표 검증은 파서와 `candidatesFor`가 맡는다.

## 성능 측정

이 PC의 네트워크에서 측정했다. **휴대폰 값이 아니고 Render 경유도 아니다.** 실제 호출 19회, HTTP 오류 0건.

| 구간 | 값 | 범위 |
|---|---|---|
| 사진 전처리 (줄이기와 JPEG 인코딩) | 41~74ms | 데스크톱 Chrome, E2E 5회 |
| 전송과 API 왕복 | 중앙값 342ms, 대부분 290~681ms | 원장 19회 |
| 첫 호출 | **7,414ms**, 다음 세션 첫 호출 1,482ms | 모델 준비 시간 추정, 원인 미확인 |
| 응답 해석 | 0.02~0.66ms | 19회 |
| 결과 변환 (`candidatesFor`) | 중앙값 0.02ms, 최대 0.55ms | 26개 응답 |
| 페이지 요청→응답 | 319~1,495ms | E2E 5회 |
| 전체 처리 | 849~1,953ms | E2E 5회. 시험 도구의 관찰 지연이 포함되어 실제보다 길다 |
| 올리는 크기 | 161~417KB (JPEG), 214~556KB (base64) | E2E 5회 |
| 모델로 보낸 크기 | 193KB~1.64MB (base64) | 원장 19회. 최대는 1.2MB 평가 사진 |
| 응답 크기 | 280B~3.8KB | 원장 19회 |

**위험:** 첫 호출이 7.4초라 서버 제한 10초에 가깝다. 넘으면 사용자는 실패 안내를 받고 점검은 계속할 수 있다. 제한은 바꾸지 않았다.

## 사용자 흐름

P12-E UI를 그대로 썼다. 실제 모델로 QR 진입, 동의, 사진 선택, 후보 표시, 점검 복귀를 Chrome에서 확인했다. 스크린샷은 증거 폴더에 있다.

- **동의 전 전송 없음:** 동의 전에 파일을 골라도 요청 0건을 확인했다.
- **미지원 부품:** 12V와 저전도는 버튼이 없어 호출하지 않는다.
- **못 찾으면:** `그림 안내와 차량 설명서로 찾아 주세요`로 안내하고 점검은 그대로다.
- **권유 없음:** 캡 개방, 보충, 접촉을 권하는 문구를 금지하는 기존 시험이 통과한다.

## 후속 AR 통합

이번에 AR·추적은 구현하지 않았고 QR·WebXR 계약도 바꾸지 않았다. 응답에 다음 기록을 넣어 재사용할 수 있게 했다. 아래는 실제 E2E 응답(`commons-032`)이다.

```json
{
  "partId": "washer-fluid-cap",
  "status": "EXPERIMENTAL",
  "candidates": [{ "score": 0.762, "box": [0.0769, 0.6802, 0.1209, 0.0991] }],
  "detection": {
    "modelId": "engine-bay-parts/1",
    "modelClass": "Windshield Wiper Fluid",
    "coordinates": "normalized-top-left-xywh",
    "image": { "width": 1183, "height": 888 },
    "inferredAt": "2026-11-07T13:11:33.605Z"
  }
}
```

```text
최초 AI 탐지 → 2D 정규화 좌표 + 사진 크기 + 시각 → 로컬 추적 → 실패 시 재탐지 → 3D AR 앵커
```

**구조적으로는 가능하지만 먼저 탐지 성능이 받쳐 줘야 한다.**

- 왕복 300~700ms이므로 한 번씩 찍는 재탐지에는 맞고 프레임마다 호출하는 데는 맞지 않는다. 호출 비용과 사진 전송 동의도 프레임 단위와 맞지 않는다.
- Recall이 0.31~0.43이라 첫 탐지부터 자주 실패한다. 여러 장을 시도하는 흐름이 필요하다.
- 로컬 추적, 휴대폰 성능, 2D에서 3D로 올리는 정확도는 **NOT_RUN**이다.
- 후보를 사용자가 확인한 뒤에만 추적하게 해야 한다. 오탐을 공간에 고정하면 더 그럴듯해 보이기 때문이다.

## Render 배포 전 남은 승인

이번 PR은 Render를 바꾸지 않는다. 켜려면 다음이 필요하다.

1. **라이선스:** `yolov8n`의 AGPL-3.0 계열과 호스팅 경유 적용 범위, 타인 소유 모델 의존([P12-C](p12-c-existing-model.md)). 법률 검토 필요.
2. **학습 데이터 권리:** 2,378장의 원출처 미확인.
3. **사진 처리 조건:** Roboflow의 호스팅 이미지 보관 조건 미확인. 개인정보 검토 필요. 동의 문구에도 그렇게 적혀 있다.
4. **정확도:** 사람이 검수한 라벨과 사전 기준으로 부품별 평가.
5. **운영 변경 승인:** API 키 환경변수, 진입점, Start Command, Render 빌드에 `tools/vision-poc` 포함 여부, WebXR 진입점과의 결합.
6. **비용과 상한:** 원장은 로컬 전용이다. 운영에서는 별도 비용 상한이 필요하다.
7. **실기기:** Z Flip8에서 촬영·동의·탭 폐기·전처리 시간 확인 (`NOT_RUN`).

**위 1~3이 풀리기 전에는 운영 기능을 켜지 않는다.**
