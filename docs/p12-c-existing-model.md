# P12-C 기존 학습 모델 재사용 검증

공개 모델 `engine-bay-parts/1`을 재학습 없이 CarScope에 쓸 수 있는지 검증했다. 실제 호스팅 API로 사진 12장을 추론했다. 실행 근거는 [증거 인덱스](evidence/p12-c/README.md)에 있다.

## 판정

**연구·비교 기준으로는 재사용할 수 있지만, 지금 상태로 CarScope 제품에 넣을 수는 없다.**

| 층 | 판정 | 근거 |
|---|---|---|
| 실제 실행 | **성공** | 호스팅 API 12/12 응답. 오류 없음 |
| 캡 위치 신호 | **가능성 있음, 예비** | 12장 예비 평가에서 Recall 0.64, 색상 규칙보다 오탐이 적음. 표본이 작아 입증은 아님 |
| 제품 탑재 | **불가 (현 상태)** | 아래 차단 사유 |
| 정식 평가 | `DATASET_REQUIRED` | `DATASET_GATE` 미충족, 수치 변경 없음 |
| Z Flip8 | `NOT_MEASURED` | 기기 없음, 모델 파일 없음 |

**제품 탑재 차단 사유**

1. **라이선스:** 모델은 `yolov8n`(Roboflow 3.0)이다. [Roboflow 안내](https://roboflow.com/licensing)에 따르면 Roboflow 3.0은 AGPL-3.0이고, 무료·Core 플랜에는 상업용 자체 호스팅이 포함되지 않는다. 프로젝트의 MIT 표시로는 해결되지 않는다.
2. **호스팅 경유의 운영 부담:** 클라우드 경로는 상업 사용이 포함된다고 안내되어 있지만, 타인의 Universe 모델에도 그대로 적용되는지는 문서에 없다. 키를 페이지에 넣을 수 없어 서버 프록시가 필요하고 사용자 사진이 외부로 나간다.
3. **데이터 출처:** 프로젝트의 MIT는 올린 사람의 표시다. 사진 2,378장의 원출처를 확인하지 못했다.
4. **성능 근거 부족:** 12장은 선별된 사진이고 라벨은 사람의 검수를 받지 않았다. 모델 소유자가 공개한 수치도 낮다(아래).
5. **제3자 소유:** 소유자가 언제든 바꾸거나 내릴 수 있다.

## 1. 평가 결과 (`EXPLORATORY_EVALUATION`, 예비)

사진 12장(양성 11, 음성 1), IoU 0.5, `Windshield Wiper Fluid`만 대상. 공식 지표가 아니다.

| 신뢰도 기준 | TP / FP / FN | Precision (95%) | Recall (95%) |
|---|---|---|---|
| 0.05 ~ 0.3 | 7 / 1 / 4 | 0.88 (0.53~0.98) | 0.64 (0.35~0.85) |
| 0.4 | 6 / 0 / 5 | 1.00 (0.61~1.00) | 0.55 (0.28~0.79) |
| 0.5 (기존 PoC 기본값) | 5 / 0 / 6 | 1.00 (0.57~1.00) | 0.45 (0.21~0.72) |
| 0.6 | 2 / 0 / 9 | 1.00 (0.34~1.00) | 0.18 (0.05~0.48) |

**mAP@0.5 = 0.64.** 반환된 예측 전체(신뢰도 0.05 이상)로 계산했다. 클래스가 하나이므로 AP@0.5와 같다.

### 색상 규칙과 비교

같은 사진 12장, 같은 라벨이다.

| | 색상 규칙 | 모델 (0.05~0.3) | 모델 (0.5) |
|---|---|---|---|
| TP / FP / FN | 5 / 7 / 6 | 7 / 1 / 4 | 5 / 0 / 6 |
| Precision | 0.42 | 0.88 | 1.00 |
| Recall | 0.45 | 0.64 | 0.45 |
| mAP@0.5 | 계산 불가 | 0.64 | |
| 다른 액체 캡 오탐 | 1 (Skoda 냉각수) | 0 | 0 |

| 탐지한 사진 | 차량 |
|---|---|
| 둘 다 | Skoda Rapid, Kia Sportage, Corolla, Ora Funky Cat |
| 모델만 | Kia K5, Mercedes C200(청록 캡), Peugeot e-208(짙은 파랑 캡) |
| 색상 규칙만 | Toyota Yaris |
| 둘 다 놓침 | Nissan President, Dacia Spring, Prius v(검은 캡) |

오탐이 크게 줄어든 것이 가장 뚜렷한 차이다. 다만 95% 구간이 겹치고 표본이 12장이라 **더 낫다고 입증한 것은 아니다.** 모델도 검은 캡을 찾지 못해, 색이 다른 캡에 강하다고 말할 수 없다.

## 2. 캡인가 리저버 전체인가

**이 사진들에서는 캡을 잡는다.** 리저버 전체가 아니다.

- 탐지 상자 8개 중 캡 위의 7개는 라벨과 IoU 0.52~0.81이고, 면적은 캡 라벨의 1.2~1.9배다.
- 겹쳐 그린 이미지에서 상자가 캡과 목 윗부분을 감싼다. 긴 넥이 보이는 Kia, Yaris, 탱크가 보이는 Ora, Peugeot에서도 탱크 전체로 커지지 않았다.

따라서 캡 위치 안내에 의미가 맞는다. 다만 소유자가 라벨 기준을 밝힌 자료는 찾지 못했으므로 이 11장에서 관찰한 결과다. 그래서 어댑터의 매핑은 유효하다.

## 3. 숫자 클래스 문제

모델의 클래스가 **이름 26개와 숫자 26개**로 나뉜다. 응답 173건 중 86건이 숫자 클래스다.

**`"3"`은 `Windshield Wiper Fluid`의 중복 라벨로 보인다.** 근거:

- 프로젝트 라벨 수가 둘 다 807개로 같다. 다른 클래스도 대부분 쌍을 이룬다(`7`=1007=`Engine Oil Fill Cap`, `9`=732=`Air Filter Cover`, `13`=664=`Radiator` 등).
- 실제 응답에서 `"3"` 상자가 캡 위에 나왔다. 11장 중 8장에서 캡과 겹치며, Nissan(0.71)과 Yaris(0.67)는 이름 클래스가 놓친 캡을 `"3"`이 잡았다.

단, 소유자의 설명으로 확인한 사실은 아니고 관찰에서 추론한 것이다.

**이 때문에 신뢰도가 두 이름으로 나뉘었을 가능성이 있다.** 요청대로 다른 클래스를 정답으로 세지 않았고 어댑터도 바꾸지 않았다. 대신 영향의 크기만 별도 분석했다(`exploratory-alias-analysis.mjs`).

| 분석: `"3"`을 같은 부품으로 볼 때 | TP / FP / FN | Precision | Recall |
|---|---|---|---|
| 기준 0.3 | 9 / 1 / 2 | 0.90 | 0.82 |
| 기준 0.5 | 8 / 0 / 3 | 1.00 | 0.73 |

**보고 결과가 아니라 민감도 분석이다.** 사후에 라벨을 보고 정한 가설이어서 낙관적으로 치우친다. 이 매핑을 쓰려면 소유자의 설명이나 새 데이터로 먼저 확인해야 한다.

### 모델 소유자가 공개한 수치

Roboflow 메타데이터의 값이며 이번에 측정한 것이 아니다. 전체 mAP@0.5는 검증 42.09%다. 테스트 분할의 클래스별 값은 다음과 같다.

| 클래스 | 대상 | Precision | Recall | mAP@0.5 |
|---|---|---|---|---|
| `Windshield Wiper Fluid` | 84 | 0.47 | 0.82 | 0.44 |
| `3` | 68 | 0.38 | 0.87 | 0.39 |

이번 12장의 예비 수치와 Precision 차이가 크다. 학습 데이터 쪽은 중복 라벨 때문에 낮아졌을 수 있고, 이번 12장은 선별돼 높아졌을 수 있다. 어느 쪽도 일반 성능으로 쓰지 않는다.

"관찰"은 응답과 겹쳐 그린 이미지로 확인한 사실이고, "추정"은 원인 가설이다. 12장으로는 추정을 검증할 수 없다.

### 혼동 부품과 음성 사진

표본은 냉각수 캡 3개와 브레이크액 캡 1개뿐이다. 넷 모두 `Windshield Wiper Fluid`로 오인되지 않았다. 다른 액체 캡 오인식이 없다고 말하기에는 턱없이 적다.

브레이크액 근접 사진(Skoda Fabia)에서는 오탐이 없었지만, 모델은 브레이크액 리저버를 잡지 못하고 `Engine Cover` 0.55를 냈다. 다른 클래스의 신뢰성이 낮을 수 있다는 신호다.

## 7. MediaPipe 호환성

**이 모델을 MediaPipe로 옮기는 작업은 권하지 않는다.** 응답에 따르면 호스팅 백엔드는 ONNX(fp32)다. MediaPipe는 [LiteRT와 메타데이터, 정해진 네 출력 텐서](https://developers.google.com/edge/mediapipe/solutions/vision/object_detector)를 요구하므로 변환이 필요할 가능성이 높지만, 파일을 받아 확인하지는 않았다(`NOT_EVALUATED`).

더 중요한 것은 라이선스다. 형식을 바꿔도 AGPL 조건은 그대로다. 라이선스 문제가 풀리기 전에는 변환 비용을 들일 이유가 없다. 어댑터가 필요해지면 `detector-runtime.mjs` 하나를 ONNX Runtime Web 구현으로 교체하는 설계를 쓴다.

```text
createDetector() ── 기존 계약 ──> detect(canvas) → [{categories, boundingBox}]
                                        ▲
      MediaPipe 런타임 (detector-runtime.mjs)
      또는 ONNX Runtime Web + 640×640 전처리 + 디코딩·NMS + 클래스 매핑
```

## 8. Z Flip8 통합 가능성

**`NOT_MEASURED`.** 호스팅 경로는 휴대폰 성능에 덜 의존하지만 프록시와 사진 전송이 필요하다. 기기 안 추론은 `yolov8n`이 작은 편이어서 가능성은 있으나, 파일 확보와 라이선스 문제가 먼저다. 메타데이터의 `tfjs: true`는 내보내기 지원 표시일 뿐이며 실행 확인이 아니다.

## 10. 평가 세트의 한계

[`dataset/exploratory-commons.json`](../tools/vision-poc/dataset/exploratory-commons.json): **Wikimedia Commons 12장**(양성 11, 음성 1), 차량 12종, 제조사 8곳. 이미지는 Git에 없다.

- **선별 편향:** 라이선스가 있는 후보를 제목순으로 최대 180건 받아(그 뒤는 보지 않음) 최신 승용차 46장으로 좁혔고, **워셔 기호를 읽을 수 있는 캡만** 양성으로 삼았다(116, 122, 174, 39, 47번 등 제외). 쉬운 쪽으로 치우친다.
- **라벨:** 상자와 기호 판단은 자동화된 단일 작업자(Claude)가 했고 **사람의 검수를 받지 않았다.**
- **학습 데이터 중복:** 공개 사진이어서 모델 학습 데이터와 겹칠 수 있다. 겹치면 점수가 부풀려지며 확인할 수 없다.
- **혼동 부품과 음성:** 라벨 4개와 음성 1장뿐이다.
- **대상 차량:** IONIQ 5 사진이 없다.

이번 결과는 A의 동기를 준다. 모델 구조가 작아도 캡이라는 신호를 잡을 수 있다는 예비 근거이기 때문이다. 어느 경우든 이번에는 학습하지 않았다.

**A 또는 B를 고르기 전에 하면 좋은 저비용 확인:** 사람이 라벨을 검수하고, IONIQ 5 실물 사진을 소유자 동의로 몇 장 추가해 같은 스크립트를 다시 돌린다. 호스팅 API로 사진을 보내므로 소유자 동의에 외부 전송이 포함되어야 한다.
