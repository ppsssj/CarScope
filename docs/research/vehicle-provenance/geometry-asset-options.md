# Geometry asset options — 공식 외형 이미지·3D 자산과 사용 가능성

## 1. 공식 자산 조사 결과

| 후보 | 결과 |
| --- | --- |
| Pleos 개발자 문서의 차량 이미지/3D 다운로드 | 확인한 문서(Vehicle SDK, 에뮬레이터, Virtual Console)에서 **찾지 못함**. Virtual Console의 시각화 테마는 사용자가 고르는 기능이며, 어떤 차량이 표시되는지는 설명하지 않는다. |
| Pleos Playground "Design Asset" | 이용약관 제2조①이 서비스 범위로 "Pleos Connect SDK, Fleet API, Design Asset 등"을 언급한다. 차량 외형 자산인지, 공개 범위와 라이선스가 무엇인지는 **찾지 못함**. `pleos.ai/playground/develop`은 404였다. |
| AVD OEM HMI의 흰색 차량 시각화 | 화면으로만 관찰했다(P2-A3-0). 메타데이터와 연결된다는 문서가 없다. 리소스를 추출하지 않았고, 약관상 추출해서도 안 된다(아래). |
| AOSP | `INFO_*` 기본값만 있고 차량 외형 자산은 없다. |
| Hyundai 뉴스룸 | 보도 사진만 있다(GRANDEUR·IONIQ 3 등). 3D 자산이 없고, 보도 이미지를 재사용할 권리도 확인되지 않았다. |
| Volvo | 공식 페이지에 접근하지 못했다(403). 어떤 경우든 AVD 차량과의 관련이 없으므로 대상이 아니다. |

## 2. Pleos Playground 이용약관상 제약

[Pleos Playground 이용약관](https://developers.pleos.ai/playground/external/use-policy?partnerId=672505ad-2e37-4500-8162-000bcfc05b5c&locale=ko-KR)(운영: 포티투닷 주식회사, 2025-03-28 시행). 한국어 원문을 읽고 번역·요약한 내용이며 법률 자문이 아니다.

| 조항 | 요지 | CarScope에 대한 의미 |
| --- | --- | --- |
| 제10조 | 회사가 게시한 게시물의 저작권은 회사에 있다. 이용하려면 **명시적 사전 서면 동의**가 필요하다. | 문서 속 이미지를 저장소에 복사하지 않는다. 링크만 건다. |
| 제12조 | 서비스 관련 지식재산권은 회사 소유이다. 회원가입이 사용권을 주지 않으며, 별도 사용 허락이 있어야 쓸 수 있다. | 공식 디자인을 재현하려면 별도 허락이 필요하다. |
| 제14조⑤ | 서비스 **데이터의 추출·저장·보관**과 그 후의 사용·유통·변경·복제를 금지한다. 회사 브랜드의 모방·도용과 상표·로고의 무단 사용도 금지한다. | AVD/HMI 차량 모델을 추출하거나 본뜬 형상을 만들지 않는다. |
| 제15조 | 개발도구의 분해·디컴파일·**리버스 엔지니어링**, 수정·파생물 작성, 제3자 제공을 금지한다. | 에뮬레이터 이미지 분석으로 출처를 밝히는 방법은 쓰지 않는다. |
| 제14조① / 제7조 | 이용자는 승인 범위 안의 제한된 사용권만 가진다. | 자산 사용은 별도 승인을 전제로 한다. |

## 3. 선택지 비교

| 선택지 | 법적 상태 | 정확도 | 판정 |
| --- | --- | --- | --- |
| A. 현재 방식 유지: 독립 procedural SUV + AVD 치수 | 자체 제작이고 AOSP 기본값은 Apache-2.0 소스의 수치이다. | 차급과 외곽 치수만 반영한다. | **권장(현행)** |
| B. AVD/HMI 3D·이미지 추출 후 재사용 | 약관 제14·15조 위반 소지가 있고 프로젝트 금지 사항이다. | — | **NO-GO** |
| C. Pleos "Design Asset" 공식 제공분 사용 | 제공 여부·범위·라이선스를 확인하지 못했다. | 미상 | **보류** — 42dot/Pleos에 공식 문의하고 서면 라이선스를 받은 경우에만 진행 |
| D. 특정 실차(GRANDEUR, IONIQ 3, XC90 등) 형상 재현 | OEM 디자인권·상표 문제가 있고, AVD와의 대응 근거도 없다. | 오식별 위험 | **NO-GO** (AVD 차량이 그 모델이라는 근거가 없다) |
| E. 라이선스가 명시된 제3자 3D(CC0/CC-BY 등) | 자산별 라이선스 확인이 필요하다. 실차 브랜드 형상이면 별도 권리 문제가 있다. | 일반 차급 수준 | 필요하면 **브랜드 없는 generic 모델만** 검토 |

## 권고

1. **Geometry는 변경하지 않는다.** 현재 SUV는 AVD 치수(AOSP 기본값과 동일)로 만든 독립 형상이며, 이번 조사로 그 성격이 더 분명해졌다.
2. **출처 표기 보강(후속 PR 제안, 이번에는 미구현).** `vehicle-profile.mjs`의 치수 provenance에 `upstreamMatch: "AOSP reference VHAL DefaultProperties.json (android11–main)"`를 추가하고, `oemIdentity: null` 유지를 명시한다. 화면 캡션의 "AAOS AVD reference envelope, OEM shape unverified"는 정확하므로 유지한다.
3. **index 7 해석.** AOSP의 "radius"와 SDK의 "diameter" 표기가 다르다. 회전 반경·직경을 쓰는 기능을 만들 때는 이 차이를 명시하고 실측 근거 없이 단정하지 않는다.
4. **공식 자산이 필요하면** Pleos/42dot에 Design Asset의 범위와 라이선스를 문의하고, 서면 허락과 provenance 기록을 확보한 후 별도 과제로 진행한다.
5. **문구 정책.** 문서·UI에서 "Hyundai 42dot Connect 2024"를 차량 이름처럼 조합하지 않는다. 치수를 "XC90 제원"이라고도 부르지 않는다. 쓸 수 있는 표현은 "Pleos AVD가 반환한 시뮬레이션 메타데이터"와 "AOSP 참조 VHAL 기본 치수"이다.
