# P12-G 라벨 검수 도구와 재평가

P12-F의 사진 26장과 저장된 모델 응답을 사람이 직접 검수하고, 완료된 검수만으로 성능을 다시 계산하는 로컬 도구다. 실행 근거는 [증거 인덱스](evidence/p12-g/README.md)에 있다.

## 판정

**도구는 준비됐고 검수는 시작 전이다. 상태는 `AWAITING_HUMAN_REVIEW`다.**

| 항목 | 값 |
|---|---|
| 사람 검수 완료 | **0 / 26장** |
| 수정된 Ground Truth | **0개** |
| 검수 후 평가 수치 | **없음** (`HUMAN_REVIEW_PENDING`) |
| Roboflow 추가 호출 | **0회**, 원장 19/20 그대로 |
| 모델 성능 | **변경 없음.** 학습하지 않았다 |

P12-F 수치는 검수받지 않은 초안 기준의 예비 값이며 이번에도 그대로 예비 값이다. 도구로 다시 계산해 같은 값이 나오는 것은 확인했다.

| 부품 | TP / FP / FN | Precision | Recall | F1 | 일치 상자 IoU 중앙값 |
|---|---|---|---|---|---|
| 워셔액 | 6 / 0 / 8 | 1.00 | 0.43 | 0.60 | 0.63 |
| 냉각수 | 4 / 2 / 9 | 0.67 | 0.31 | 0.42 | 0.84 |
| 브레이크액 | 7 / 1 / 10 | 0.88 | 0.41 | 0.56 | 0.66 |
| 퓨즈박스 | 1 / 0 / 2 | 1.00 | 0.33 | 0.50 | 0.91 |
| `Battery` (측정만) | 6 / 0 / 8 | 1.00 | 0.43 | 0.60 | 0.83 |

## 실행

```powershell
Set-Location tools\vision-poc
npm ci --ignore-scripts
npm run review               # http://127.0.0.1:8210
npm run review:report        # 데이터 확인과 재평가. 호출 없음
```

- 검수 결과는 `C:\CarScope-External\p12-g\label-review.json`에 저장한다. `--review <경로>`로 바꿀 수 있지만 저장소 안의 경로는 거부한다.
- 사진이나 응답이 없거나 해시가 다르면 서버가 시작하지 않고 `BLOCKED`와 사유를 보여 준다. 대체 사진을 쓰지 않는다.

## 검수 절차

1. 오른쪽 위 **검수자**에 이름이나 식별값을 직접 입력한다. 기본값은 없고 창을 새로 열면 다시 입력한다.
2. 왼쪽 목록이나 **집중 사례**에서 사진을 고른다.
3. 부품 탭을 고르고 AI 예측(점선)과 사진을 비교한다. 흰 가는 선은 P12-F 초안이다.
4. 부품을 찾으면 **부품 전체 그리기**나 **캡 그리기**로 그린다. 초안이 맞으면 **초안 박스 가져오기**로 가져와 고친다.
5. **판정**을 직접 고른다. 박스를 가져와도 판정은 바뀌지 않는다.
6. 6개 부품을 모두 판정한 뒤 **검수 완료 저장**을 누른다. 중간이면 **임시 저장**을 쓴다.

휠로 확대·축소하고 빈 곳을 끌어 이동한다. 박스는 끌어 옮기고, 모서리로 크기를 바꾸고, Delete나 목록의 **삭제**로 지운다. 저장 안 된 수정이 있으면 상단에 표시되고, 사진을 옮기거나 창을 닫을 때 경고한다.

## 판정

| 상태 | 뜻 | 박스 | 평가에서 |
|---|---|---|---|
| `UNREVIEWED` | 사람 검수 전 | 그리는 중일 수 있음 | 제외. 완료 저장 불가 |
| `PRESENT` | 있고 위치 확인 | 전체 또는 캡 1개 이상 필수 | 정답. 못 찾으면 FN |
| `ABSENT` | 없다고 확인 | 부품 박스 금지 | 부품 없음. 상자가 있으면 FP |
| `UNKNOWN` | 사진으로 판단 불가 | 부품 박스 금지 | **제외.** 상자가 있어도 FP가 아님 |
| `NEEDS_REFERENCE` | 외부 근거 필요 | 부품 박스 금지. 메모나 근거 필수 | **제외** |

`UNKNOWN`과 `ABSENT`는 평가 결과가 다르다. 시험이 같은 상자로 이를 확인한다.

박스 유형은 부품 전체, 캡, 제외 영역(모델이 집어도 맞고 틀림을 세지 않음), 고전압 영역(12V 배터리 검수에서만)이다. 부품 하나에 박스를 여러 개 둘 수 있다. 캡은 자기를 포함한 전체 박스에 붙고, 전체 박스 없이 캡만 보이면 캡 자체가 부품 하나로 계산된다.

## 사람 검수를 지키는 규칙

코드가 사람인지 증명할 수는 없다. 대신 다음을 막는다.

- 초안을 답으로 채우지 않는다. 처음 열면 정답 박스 0개, 판정 `UNREVIEWED`다.
- 검수자는 입력값뿐이다. 코드에 기본값이나 생성 로직이 없다.
- 완료 저장은 6개 부품 판정과 검수자, 사진 해시 일치가 모두 있어야 한다.
- 시험 데이터는 파일에 `synthetic: true`로 남고 평가는 `SYNTHETIC_NOT_A_REVIEW`로 표시한다. 그런 파일은 실제 도구에서 열리지 않는다.
- 검수 파일은 저장소 밖에만 저장한다. `labelsReviewedByPerson: false`와 P12-F 라벨 파일은 어떤 경로로도 바뀌지 않는다.

**Claude는 이 도구로 실제 검수 파일을 만들지 않았다.** 실제 사진 확인은 저장 없는 읽기 전용 실행으로만 했다.

## 저장 구조

```json
{
  "schema": "carscope-label-review-v1",
  "synthetic": false,
  "sourceLabelsSha256": "...",
  "images": {
    "commons-032": {
      "imageSha256": "...", "complete": true, "reviewer": "직접 입력한 값", "revision": 2, "savedAt": "...", "completedAt": "...",
      "parts": {
        "washer": { "partId": "washer-fluid-cap", "status": "PRESENT", "boxes": [], "caps": [[0.08, 0.69, 0.11, 0.09]], "ignore": [], "hv": [], "note": "", "reference": "", "reviewedAt": "...", "reviewer": "..." }
      }
    }
  }
}
```

- **좌표:** `[left, top, width, height]`, 사진 대비 비율, 원점 왼쪽 위.
- **해시:** 사진이 바뀌면 그 기록은 `INVALIDATED`로 표시되고 평가에서 빠진다.
- **기록:** 저장마다 `label-review.json.history.jsonl`에 전체를 덧붙인다.
- **비교:** `npm run review:report`가 P12-F 초안과 달라진 판정과 박스를 목록으로 낸다.
- **원자적 저장:** 임시 파일에 쓴 뒤 이름을 바꾼다. 잘못된 파일은 덮어쓰지 않고 시작을 거부한다.
- **동시 저장:** 다른 창이 먼저 저장했으면 409로 거부한다.

## 재평가 규칙

| 상태 | 언제 | 표시 |
|---|---|---|
| `HUMAN_REVIEW_PENDING` | 완료 0장 | 검수 후 수치 없음. 초안 수치만 `UNREVIEWED_DRAFT`로 |
| `PARTIALLY_REVIEWED` | 일부 완료 | 수치마다 이 표시. 전체 성능이 아님 |
| `HUMAN_REVIEWED` | 26장 완료 | 완료 기준 수치 |

- **센다:** 검수 완료 사진의 `PRESENT`, `ABSENT`만. 임시 저장, `UNKNOWN`, `NEEDS_REFERENCE`, 해시가 다른 기록은 세지 않는다.
- **기준:** 신뢰도 0.4, IoU 0.5 고정. 다른 임계값 표는 참고용이고 최적값을 고르는 코드가 없다.
- **비교:** 초안 전체, 같은 범위의 초안, 검수 결과를 따로 낸다. 범위가 달라서 생기는 차이와 라벨 수정 때문에 생기는 차이를 구분하기 위해서다.
- **내용:** TP, FP, FN, Precision, Recall, F1, 95% 구간, 일치 상자 IoU, FP가 놓인 곳(다른 부품, 고전압, 부품 근처, 라벨 없는 곳), 초안 대비 수정 항목.
- **저전도 냉각수:** 판정은 기록하지만 모델 클래스가 없어 `NO_MODEL_CLASS`다.

**해석 주의:** 26장은 평가에 이미 쓰인 사진이다. 검수가 끝나도 선별 편향과 학습 데이터 중복 가능성은 남고 정식 `DATASET_GATE`를 충족하지 않는다. "라벨을 믿을 수 있는 예비 평가"이지 독립 평가가 아니다.

## 집중 사례

**집중 사례** 필터에 P12-F 관찰 8개가 있다. 예비 관찰이고 답이 아니다: `new-08`, `commons-039`, `commons-170`, `commons-024`, `commons-066`, `new-06`, Nissan Leaf 2장, Chevrolet Bolt 3장.

## 보안과 경계

| 항목 | 방식 |
|---|---|
| 네트워크 | `127.0.0.1`만 수신. 다른 Host와 Origin은 403. 페이지 CSP는 자기 서버만 허용 |
| 쓰기 | 전용 헤더와 JSON 형식이 필요해 다른 사이트에서 보낼 수 없음. 본문 256KB 제한 |
| 파일 접근 | 고정 경로와 라벨 파일에 있는 사진 ID만. 경로 입력을 받지 않음 |
| 모델과 키 | 호출 코드와 키 읽기가 없음. 시험이 소스 전체를 검사 |
| 운영 | Render 코드 그래프 밖. `RENDER` 환경에서 시작 거부. 모바일 서비스, QR, 세션, Supabase, 플래그 변경 없음 |

사진은 저장소에 넣지 않는다. 화면의 **출처** 링크는 눌렀을 때만 Commons를 연다.

**제약:** 박스 그리기는 마우스 전용이다. 키보드로는 판정, 메모, 박스 선택, 삭제만 할 수 있다. 서버를 띄운 사람이면 이 PC의 다른 프로그램도 같은 주소로 저장할 수 있고, 인증은 없다.

## 다음 단계: IONIQ 5 실물 사진

**먼저 26장 검수를 끝낸다.** 그 결과로 어떤 부품이 실제로 약한지 본 뒤 찍을 사진을 정한다.

1. **권리:** 차량·사진 소유자의 서면 동의. 평가 사용, 외부 AI 전송, 보관 기간을 나눠 받는다. 번호판과 사람은 찍지 않거나 가린다.
2. **근거:** 차량 연식과 트림을 먼저 기록하고 공식 설명서로 12V 배터리, 퓨즈박스, 냉각수 계통과 저전도 사용 여부를 확인한다. 추측으로 라벨링하지 않는다.
3. **촬영:** 전체 보닛, 부품별 중간 거리, 근접을 주간·야외 그늘·저조도로 찍는다. 차량 2대 이상을 권한다. 부품 표기를 읽을 수 있는 사진을 따로 남긴다.
4. **기준 먼저:** 사진을 모델에 보내기 전에 부품별 합격 기준을 정해 커밋한다.
5. **라벨:** 이 도구로 사람이 검수한다. 사진을 라벨 파일에 추가하되 기존 26장과 **별도 세트**로 집계한다.
6. **호출:** 호출 예산을 먼저 승인받는다. 남은 호출은 1회뿐이라 사진 수만큼 별도 승인이 필요하다.
7. **혼동 시험:** 12V와 고전압 부품, 일반 냉각수와 저전도를 같은 세트에서 본다.
