# P10 통합 점검 패널 — 정보 구조·이동·문구 통일 (PR #2)

PR #117(3D 라벨·선택 강조·상태 색)에 이어 차량 점검 패널의 정보 구조, 화면 이동, 문구와 시각 요소를 하나의 규칙으로 정리했다. 새 기능이 아니라 기존 기능의 표시 계층(Presentation)과 필요한 이동 상태만 바꿨다. 결과는 [증거 인덱스](evidence/p10-panels/README.md)에 있다. **데스크톱 Chrome 측정이며 AVD, Android WebView, 실제 손가락 터치, 스마트폰, 실차는 `NOT_RUN`이다.**

| 부품 결과 | 결과 카드, 세션·과거·SDK 3구역, `전체 점검 요약으로` | 같은 순서. 과거 기록 진입(저장된 과거 기록·서버)과 SDK(접힘)는 유지 |

| 과거 점검 기록 | `기록 목록으로`, `이전 화면으로` | `뒤로`. 그 밖의 History 코드·문구는 바꾸지 않았다(아래 남은 문제) |

## 화면 이동

| 규칙 | 구현 |
|---|---|
| 뒤로 가기는 그 화면을 연 곳으로 | 부품 결과와 전체 요약은 열린 화면을 `back`에 기억한다(`inspection-flow.mjs`의 `returnPoint`). 보닛 목록에서 연 결과는 보닛 목록(보닛이 열린 채), 타이어 상세에서 연 요약은 그 타이어, 요약 → 결과 → 뒤로 → 뒤로는 요약 → 원래 화면이다. 결과 사이 이동은 결과 화면을 바꿀 뿐 쌓지 않는다. History를 거쳐도 유지된다. 기억 깊이는 4로 제한한다 |
| 보닛 | 돌아갈 화면의 보닛이 닫혀 있으면 `HOOD_CLOSING`이 그 화면(`resume`)으로 끝난다. 열려 있어야 하면 기존 보닛 구동이 연다 |
| 요약을 불필요하게 지나지 않음 | 결과 화면의 뒤로 가기는 더 이상 요약으로 고정되지 않는다 (P0-3) |
| 하나의 BACK | 패널 `뒤로`, 상단 바 `← 뒤로`, Escape, Android Back(`inspectionBack`)이 같은 이벤트 하나를 보낸다. 모든 패널 뒤로 버튼은 `뒤로` 한 가지다 (P2-2) |
| 카메라·선택 | 돌아간 화면의 `cameraGoal`·`hoodTarget`·`component`가 원래 화면과 같다. 보닛 목록으로 돌아가면 선택이 해제된다 |
| 점검 종료 | 이번 점검에 응답(확정 전 포함)·받은 결과·진행 중인 스마트폰 점검이 있을 때만 대화상자에서 지워지는 범위를 보여 주고 확인을 받는다. 개요에서의 뒤로 가기도 같은 경로다(이전에는 확인 없이 세션이 지워졌다). 대화상자에서 뒤로/Escape는 취소다. "저장된 과거 점검 기록은 지워지지 않습니다"를 함께 쓴다 |
| QR 보호 | PR #117의 잠금 규칙(라벨 잠금·선택 부품만 표시) 그대로. QR 표시 중 종료·홈 이동은 확인 없이 일어나지 않는다 |

Primary는 그 화면의 실행 동작(스마트폰으로 점검하기, 결과 확정, 종료 확인)만, 이동은 모두 Secondary다. 차량 앱 연결이 없는 기기(데스크톱 브라우저 등)에서는 `스마트폰으로 점검하기`가 비활성이고 이유를 옆에 쓴다(지원되지 않는 기능을 지원되는 것처럼 보이지 않도록).

## 개발용 정보 분리

| 이전에 보이던 값 | 이후 |
|---|---|
| `USER_REPORTED`, `MOBILE / USER_REPORTED` | "이 화면에서 직접 입력", "스마트폰 점검". 코드 값은 개발자 정보와 `data-source` |
| `ESTIMATED_GEOMETRY · …` 배지 | `추정 모델` / `참조 모델` / `위치 표식` 배지 + 한 문장 |
| Native 연결·오류 문구, 토스트 | "차량 앱", "스마트폰 점검" 등 평이한 문장. 원래 코드(`알림 코드 …`)와 연결 상태 원문은 개발자 정보 |
| `Capability`, `Availability`, `sessionPhase`, featureId, SDK true/false 설명 | 접힌 "차량 연동 상태 · 개발자 정보"로 이동(모든 `details`는 닫힌 채 시작) |
| `inspectionId`, `bindingId`, `digest`, proof, 원본 JSON | 접힌 "개발자 정보"(`debug-admin`) |
| ISO 시각 문자열 | 기기 시간대의 날짜·시각. 원래 값은 `datetime` 속성과 개발자 정보에 그대로 |

## 시각 통일

새 색을 만들지 않고 기존 토큰(`--surface`, `--surface-2`, `--line`, `--accent`, `--warn`, `--muted`, `--faint`)만 썼다. 카드·결과 상자·진행 현황은 같은 배경·1px `--line` 테두리·10px 반경이다. 청록은 선택과 Primary에만, 결과 색은 상태 배지에만 쓴다. 패널의 모든 버튼은 줄바꿈을 허용해 좁은 화면에서 잘리지 않는다. 토스트는 측면 패널을 뺀 빈 영역의 가운데에 놓는다(P2-5). 프로그램이 제목으로 옮긴 초점에는 테두리를 그리지 않는다(P2-7). 종료 확인 대화상자는 3D·패널·라벨을 비활성(inert)으로 만든다.

## 바꾸지 않은 것

Pleos SDK 데이터 계약·관측 시각·STALE 정책, Android Native QR 생성·인증·수신, 모바일 점검·AI(Roboflow/GPT Vision), Render 서버, Supabase·DB 스키마, 결과 원본·상태 계약(`mobile-result-contract.mjs`, `inspection-results.mjs`, `native-inspection-results.mjs`), 결과 선택·저장, History 저장소·클라이언트·계약, PR #117의 라벨·강조·터치 선택(`part-labels.mjs`, `pickExact`), PR #98 카메라 프레이밍(`inspection-camera.mjs`).

## 남은 UX 문제와 위험

- **P1-13 OPEN.** 얇은 부품의 손가락 대상은 PR #117 상태 그대로다. 이번 작업으로 해결됐다고 보지 않는다.
- **P1-8 OPEN.** 상세 화면에서 다른 부위를 3D로 고르는 것은 PR #117 터치 선택 규칙을 바꾸는 일이라 하지 않았다.
- ~~History 카드의 내부 값, History에서 연 부품 결과의 뒤로 가기~~ → [History UX 최종 보완](p10-history-ux-final.md)에서 해결.
- 같은 부품에 Primary가 둘인 화면이 있다(타이어: 결과 확정, 스마트폰으로 점검하기). 둘 다 실행 동작이다.
- 종료 확인이 생겨 응답이 있는 세션에서 AVD 자동화 스크립트(`avd-android-inspection.mjs`)가 종료 탭 뒤 확인 탭을 한 번 더 해야 할 수 있다. 응답 없는 기존 시나리오는 그대로 즉시 종료된다. **AVD는 NOT_RUN.**
- Android Back은 같은 `dispatch`를 거치므로 대화상자 취소·확인 규칙이 같다고 보지만, 실제 WebView에서는 확인하지 않았다(NOT_RUN).
- 회귀 위험: 모바일 요청 버튼은 연결이 없으면 비활성이다. 실제 Android에서 어댑터가 연결되기 전 짧은 순간에도 비활성으로 보일 수 있다(연결은 세션 시작 시 동기 설정). 결과 원본·수신·선택·QR·AI·Supabase 코드는 바꾸지 않았고 관련 Node·브라우저 테스트가 통과한다.
