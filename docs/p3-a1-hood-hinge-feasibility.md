## 5. 각도별 충돌 검사

- **거리**: 점-삼각형 6쌍과 선분-선분 9쌍 중 최소값으로, 두 삼각형 사이의 정확한 유클리드 거리다.

## 8. GLB vs SVG 구현 가능성

P2-A7 `mesh-svg`로 보닛 자세 프레임을 만들었다. 설정은 축 A, 0/15/30/45°이고, 모든 자세에 같은 카메라를 썼다. 카메라는 닫힌 차량과 45° 보닛을 함께 담도록 맞췄다.

| 확인 | 결과 |
|---|---|
| 투영 | 회전한 보닛 정점의 투영 경계와 추적된 SVG 보닛 영역 경계의 차이가 최대 0.07 / 0.22 / 0.22 / 0.10 px |
| 원본 보존 | 0° 자세를 기본 카메라로 만든 결과가 P2-A7 `ioniq5.svg`와 바이트 단위로 같다(SHA `7562f740…`). P2-A7 CLI 출력 3개 파일도 변경 없음 |
| 차체·보닛 경계 | 보닛 영역 수 5/4/3/3. 경계선은 기존 공유 체인 규칙을 따름(시트 확인) |
| 깊이 가림 | 열린 보닛이 앞유리·실내를 가리고, 보닛 아래 빈 공간(바닥판·램프 하우징)이 드러난다. 보이는 삼각형 8,096 → 8,244 |
| 결정성 | 같은 입력이면 SHA가 같다(Node 보고서와 합성 테스트) |
| 보닛 강조 | `regionOutline`으로 외곽 경로 1개만 추가(+0.6–0.8 KB) |
| 내부 형상 추가 | 검증용 상자를 일반 부품처럼 넣으면 자체 영역(1개)으로 그려지고 깊이 정렬된다(`…-SYNTHETIC_DEBUG_PLACEHOLDER.svg`, 166 KB) |

**SVG 생성이 가능하다는 것과 부드러운 애니메이션이 가능하다는 것은 다르다.** 프레임 사이는 보간되지 않는다. 15° 간격 4프레임은 단계 전환일 뿐이다. 부드럽게 보이려면 더 많은 프레임(예: 2–3° 간격, 10–15장)이 필요하고, 자산 크기가 그만큼 늘어난다.

## 11. P3-A2 내부 부품 모델링 사전 요구사항

진입은 **조건부로 가능**하다. 보닛 개폐 Geometry(분리·회전·복원·충돌 검사)는 갖추어졌다. 하지만 다음이 먼저다.

1. **출처**: 내부 부품의 위치·외형 자료를 확보해야 한다(6절 목록). 정비 매뉴얼, 부품 카탈로그 도면, 직접 실측 중 하나. 출처가 없으면 형상을 만들지 않는다.
2. **개방 각도 정책**:
   - 실차 기준 기본 개방 각도는 정하지 않는다. 실제 최대 개방 각도는 UNVERIFIED다.
   - 실험 각도(예: 0/5/15/30/45/60°)는 쓸 수 있다. 다만 화면과 자산에 `SIMULATION_ONLY`로 표시한다.
   - 실차 각도는 정비 매뉴얼이나 실측 자료를 확보한 뒤에만 정한다.
3. **축 후보**:
   - A(원본 그룹 원점, UNVERIFIED)와 C(Geometry 탐색, 미검증 시각화 후보)를 나란히 비교할 수 있게 유지한다. PoC 축 선택, 같은 각도의 캡처 `04`/`07b`, 4·5절 표에서 비교한다.
   - 어느 쪽도 실제 힌지로 채택하지 않는다. 둘 다 "힌지 미검증"으로 표시한다.
4. **빈 외피 처리**: 방화벽·에이프런·커버 없이 내부 부품만 넣으면 빈 외피 사이로 바닥과 실내가 보인다. 구획 경계 구조가 내부 부품보다 먼저다.
5. **원본 이음새**: 보닛 뒤 모서리와 A필러 밑이 겹친 부분(36쌍)은 원본 그대로 두고 이음새로 집계한다. 원본 메시는 수정하지 않는다.
6. **렌더링 경로**: 8–9절 근거로, 앱 통합은 단계형 SVG 프레임부터 시작한다. 연속 3D는 JS 화면 보안 검토 후에 진행한다.
