# P13-G 타이어·와이퍼·전조등·충전구 AI 외관 분석 (DRAFT) — PR #122

기준 `origin/main` `7da3568` (PR #121 병합 후). 모바일 점검이 있는 17개 부품 모두에 GPT Vision 외관 분석 프로필이 생겼다. 새로 추가한 11개는 **DRAFT**이다.

- **DRAFT의 뜻:** 계약·MOCK 검사만 통과했고, 실제 사진으로 평가한 적이 없다. 정확도는 모른다.
- **제공 조건:** 운영자가 별도로 승인한 Vision 실험 서버에서만 제공한다. 기본 Render 서버, Release 앱, 승인되지 않은 실험 서버에서는 꺼져 있다.
- **이번 PR에서 하지 않은 것:** 새 탐지 모델 학습이나 Roboflow 모델 교체, 유료 OpenAI/Roboflow 호출, API 키 사용, Render 배포, DB 변경, enrollment 발급, AVD 실행.

## 연결된 실제 경로 (변경 사항)

**단일 출처: `part-capabilities.mjs`**
- `SUPPORT.DRAFT`를 추가하고, 11개 부품을 `ai(UNSUPPORTED, DRAFT)`로 등록했다.
- `partCapabilities()`가 단계(`stage`)를 돌려준다. 호스트가 승인을 표시하지 않으면 DRAFT 부품은 `SERVER_DISABLED`이다.

**탐지 표: `part-detection.mjs`**
- 11개 부품에 `UNSUPPORTED`, `modelClass: null` 행을 넣었다. 목적은 둘이다:
  - 모바일 진입점과 서버의 task 검사가 이 표를 읽는다.
  - 탐지 모델에 class가 없다는 사실을 기록한다.
- 다른 class로 대신하지 않는다. 탐지 라우트는 이 부품들에 404를 준다.

**분석 프로필: `part-analysis.mjs`**
- 11개 프로필이 있다. 각 프로필은 다음을 가진다:
  - 식별 규칙(`identify`)과 확인 항목(`check`)
  - 금지 항목(`never`)
  - 부품 전용 이상 코드와 한국어 라벨
  - 금지 주장 정규식(`claims`)
  - 장면 문구("on the outside of a car …")와 프롬프트 버전 `p13-g-1`
  - 화면용 위치 안내(`positionNote`)
- `offersAnalysis(partId, {allowDraft})`, `regionAllowed(..., {allowDraft})`: DRAFT는 명시적 승인이 있을 때만 제공한다. 승인되어도 `AI_CANDIDATE` 영역은 거부한다.

**서버: `part-analysis-route.mjs` (`allowDraft`)**
- 이 플래그는 호스트 설정에서만 온다. 페이지가 보내는 어떤 헤더나 상태로도 켤 수 없다(테스트에서 `X-CarScope-Draft` 같은 헤더를 보내도 404).
- 기존 검사를 순서 그대로 유지한다: 동의(428) → 프로필(404) → 영역(400) → QR 세션 task 일치(403) → CLAIMED 상태(409) → 세션별 한도·동시성 → 이미지 크기·MIME → 결과 스키마와 금지 주장(502).
- 응답의 `profileStatus`는 `DRAFT`이다.

**페이지 표시: `markPartAnalysisPage(..., {draft})` → `data-part-analysis-draft="enabled"`**
- dev 서버와 Vision 실험 서버만 설정한다.
- 실험 서버의 판단 근거는 `draftProfilesApproved(env)`(정확히 `OPERATOR_APPROVED`)이다. `/healthz`에 `draftProfiles: OFF | OPERATOR_APPROVED`로 보고한다.
- 정적 게이트 `VISION_EXPERIMENT_ENTRY_ONLY`의 허용 환경변수 목록에 이 변수를 추가했다. 동시에 정확한 비교식과 CLI 전달 방식을 검사하도록 게이트를 넓혔다.

**휴대폰:** 「점검 방법」 카드 → `사진에서 부품 직접 지정하기` → 사진(촬영·갤러리, 로컬) → 영역 직접 지정 → Crop 미리보기 → 외부 AI 전송 동의 → 분석 → 결과(관찰·의심·판단 불가 이유·재촬영 안내) → 사용자 확인 → 기존 점검으로 복귀.
- 결과 화면에는 "시험 단계의 실험 기능이에요. 실제 사진으로 정확도를 확인하지 않았어요"가 표시된다.
- 타이어·와이퍼·전조등은 "사진으로는 어느 바퀴/쪽/등인지 확인하지 않아요"를 고정 문구로 보여 준다(AI 답이 아님).
- AI 결과는 체크리스트에 자동 입력되지 않고, 제출되지 않는다.

**차량 3D:** DRAFT 부품에는 `AI 실험` 태그를 붙이지 않는다. 패널에는 "AI 외관 분석(시험 단계)은 승인된 실험 서비스에서만 제공"이라고 표시한다.

## 실제 사진 정확도 평가 계획 (미실행)

**상태:** 사진이 없고, 사람이 검수한 라벨도 없다. **정확도 수치는 없으며 추정하지 않는다.**

**시작 전에 필요한 것:**
- 사용자의 별도 승인
- 사진 사용 권한(차량·번호판·위치 정보 제거)
- OpenAI 계정, 모델, 호출 비용 확인
- 실험 서버의 일·월 호출 한도

**사진 구성 (부품 종류별):**
1. 손상 있음: 사람이 확인한 균열·찢어짐·이물질·렌즈 손상·덮개 손상
2. 눈에 띄는 손상 없음
3. 다른 부품 사진(오답 유도)
4. 부품이 가려진 사진
5. 흔들림·저조도·반사
6. 대상과 다른 곳을 지정한 영역

타이어는 바퀴 위치별, 전조등은 하우징 형태별(상향·하향 일체형 포함), 충전구는 덮개 열림·닫힘을 나눠서 구성한다.

**라벨:** 사진마다 두 사람이 각자 정답(부품 일치 여부, 보이는 이상 코드 또는 판단 불가)을 표시하고, 불일치는 따로 기록한다(P12-G 라벨 검토 절차).

**지표 (부품 종류별):**

| 지표 | 정의 | 판단 기준 |
|---|---|---|
| JSON 스키마 통과율 | 검증기를 통과한 응답 ÷ 전체 | 100%가 아니면 원인 분석 |
| 금지 주장 발생률 | `FORBIDDEN_TEXT`/`claims`로 거부된 응답 ÷ 전체 | 0이 목표. 발생하면 프롬프트 수정 후 재평가 |
| 잘못된 부품 식별률 | 다른 부품·잘못 지정한 사진을 `LIKELY_MATCH`로 답한 비율 | |
| 알려진 손상 미탐 비율 | 손상이 확인된 사진을 `NO_VISIBLE_ISSUE_DETECTED`로 답한 비율 | 가장 중요한 위험 지표 |
| 판단 보류 비율 | `INDETERMINATE` ÷ 전체 (사진 구성별) | 저품질 사진에서는 보류가 맞다 |
| 재촬영 안내 적합성 | 보류 응답의 안내가 실제 원인(초점·각도·가림)과 맞는지 사람이 판정 | |
| 지연시간·비용 | 부품별 응답 시간 분포, 공급자 사용량 기반 호출 비용 | 공식 단가와 실제 청구로만 계산 |

**판단 경계:**
- 적은 표본으로는 실험 기능 노출 여부만 판단한다. 상용 수준의 신뢰도를 주장하려면 손상 표본이 충분한 별도 평가가 필요하다.
- 결과는 P13-B 형식으로 `docs/evidence/`에 인덱스만 남긴다. 사진·응답 원문·키는 저장소에 넣지 않는다.

## 남은 위험과 차단 조건

- **정확도 미확립:** 11개는 실제 사진으로 한 번도 실행하지 않았다. 실제 모델이 금지 주장을 얼마나 자주 만드는지 모른다. 응답 검사기가 거부하지만, 거부가 잦으면 사용자는 "AI 응답을 확인할 수 없어" 실패를 자주 보게 된다.
- **전조등:** 상향·하향 일체형 하우징에서는 사진으로 기능을 구별할 수 없다. 프롬프트·응답 검사·고정 안내가 모두 구별을 주장하지 않도록 막지만, 사용자가 다른 등을 찍을 위험은 남는다.
- **타이어:** 접지면 마모처럼 사진 각도에 따라 달라 보이는 특징은 오탐·미탐 위험이 크다. 수치·한계 판정은 막았다.
- **차단 조건:**
  - 실험 서버의 현재 상태는 미확인이다(마지막 기록 11-09 `/healthz` 시간 초과).
  - DRAFT 노출에는 운영자 환경변수 추가와 재배포가 필요하다. 이 PR에서는 하지 않는다.
- **로컬 PostgreSQL E2E:** 로컬에서는 NOT_RUN이다(Docker 데몬 꺼짐). CI 결과로 확인한다.
